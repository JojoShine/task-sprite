# 本地身份与未来微信关联

## 本轮已实现
本地SQLite的local_identity表保存首次初始化时随机生成的UUID v4（userId）及createdAt。重新启动、修改设置、升级应用不改变编号；复制整份数据库会连同身份一起复制。它是本地数据所有者标识，不是登录凭据、微信openid或硬件指纹。设置中可查看与复制。当前不联网、不上传任务、不生成可绑定的二维码。

## 后续对接边界
桌面负责执行、显示与提醒；小程序负责轻量录入与维护；独立云端保存绑定后的任务及同步版本。云端账户与本地userId通过绑定关系关联，多台电脑各自生成本地身份，不能把UUID当作认证令牌。

## 拟定绑定流程（尚未实现）
1. 桌面向服务端申请短时、一次性的绑定会话，展示二维码。
2. 用户在已登录的小程序中扫码，确认将这台桌面的本地任务关联到自己的账户。二维码不直接包含长期令牌。
3. 桌面确认会话已批准，保存服务器颁发的设备凭据到系统安全存储。服务端建立账户↔本地身份的关系。
4. 首次上传前展示本地任务数量与合并说明；确认后按已有任务UUID幂等上传，保留原始创建时间与截止日期/时段。首次绑定不默默覆盖云端或本地数据。
5. 之后桌面与小程序拉取增量更新，离线操作先保留本地，恢复连接后重试。

## 同步必须补齐的契约
服务端提供serverRevision与变更游标；写入携带mutationId和baseRevision用于幂等与冲突检测。任务UUID保持稳定，删除使用墓碑；不能仅凭两端时钟的updatedAt决定覆盖。双方编辑同一任务时显式处理冲突，完成/恢复同样纳入版本。截止时间由dueDate+dueTime表示本地墙上时间（12:00/17:00），接云端前明确账户时区与跨时区规则。提醒偏好、窗口位置、通知去重和设备凭据留在设备端，不与小程序同步。

## 解除绑定与迁移
解绑撤销设备凭据并停止同步，本地任务继续可用。数据库备份会复制本地身份，若同时在多台设备使用同一备份，接入云同步前必须分配各自设备身份，不能用本地userId替代设备认证。公开服务上线前再实现设备身份、凭据存储、导出/删除和绑定审核；本轮不提前加入无服务端的同步队列或假扫码入口。
